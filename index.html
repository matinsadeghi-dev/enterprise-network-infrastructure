04 / NETWORK SERVICES

DHCP

DHCP Server 1 supplies dynamic configuration to LAN 1 clients. Server 0 (the DHCP Server 2 role) supplies LAN 2 clients.

UDP 67/68

Reserve statically addressed infrastructure devices and ensure each pool has the correct mask and gateway.

DNS

The hostname www.lab.matin.local must resolve to the actual Web Server IP.

UDP/TCP 53

The Web Server provides DNS at 10.0.0.6. Both DHCP pools advertise 10.0.0.6 as the DNS server.

HTTP

The Web Server hosts this website and serves it through HTTP.

TCP 80

Enable Services → HTTP in Packet Tracer. Confirm the DNS A record points to this device, not automatically to DHCP Server 1.

05 / ROUTING BETWEEN LANs

If static routing is used, these routes let each router reach the other LAN. Do not add duplicate routes if a routing protocol already provides them.

ROUTER 1 → LAN 2

ip route 192.10.170.0 255.255.255.240 192.10.170.17

ROUTER 2 → LAN 1

ip route 10.0.0.0 255.255.255.0 192.10.170.18

Interface names may vary by device model. Verify the actual interface configuration before pasting commands. If DNS/Web Server is on LAN 1, LAN 2 clients need a working route to LAN 1 and a correct DNS option from DHCP Server 2.

06 / TROUBLESHOOTING

CLIENT PC

ipconfig ping 10.0.0.1 ping 10.0.0.3 ping 192.10.170.17

Test the local gateway first, then known reachable addresses. A failed ping does not always prove HTTP is unavailable.

ROUTERS

show ip interface brief show ip route show running-config show cdp neighbors

SWITCHES

show interfaces status show vlan brief show mac address-table show ip interface brief

Debug checklist

  1. Confirm each infrastructure interface is up and has the correct IP/mask.
  2. Confirm each client receives a valid DHCP address, default gateway and DNS server.
  3. Verify routes exist in both directions between 10.0.0.0/24 and 192.10.170.0/28.
  4. Verify the DNS A record for www.lab.matin.local points to 10.0.0.6.
  5. Verify HTTP is enabled on the Web Server.
  6. Test by IP first, then by hostname.
